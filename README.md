# Neogen

Programming/automation-игра: Godot 4.x + Rust-ядро (детерминированная симуляция) + Lua-скрипты игрока. Сеттинг — соларпанк-утопия 2480: инженер-смотритель обслуживает «Ноосферу».

**Движок:** Godot 4.7 (4.7.2.stable, установлен через scoop, бинарь `godot` на PATH).

## Версии

| Компонент | Версия | Примечание |
|---|---|---|
| Godot | 4.7.2.stable | scoop, бинарь `godot` на PATH |
| godot-rust (gdext) | `=0.5.5`, фича `api-4-7` | последняя стабильная на crates.io, явно заявляет Godot 4.7 API; требует rustc ≥ 1.94 (локально — 1.98 stable) |
| mlua | `=0.12.1`, `lua54` + `vendored` | точечный пин, смена — гейт пользователя |
| rustc | stable (≥ 1.94) | CI использует `dtolnay/rust-toolchain@stable` |

Сборка расширения: `cargo build -p neogen-gdext --release`, артефакт копируется в `godot/bin/` (не коммитится); регистрация — `godot --headless --import` из `godot/`.

## Headless smoke-тест моста (фаза 3)

Одна команда (из корня репо; требуются собранный extension в `godot/bin/` и однажды выполненный `godot --headless --import` из `godot/`):

```sh
cd godot && godot --headless --script res://tests/smoke.gd
```

Проверяет: тик-счётчик, seeded-детерминизм двух SimNode, парковку без команд, движение до цели с конверсией координат (core (3,4) → Godot (3,-4)), совпадение дробного и цельного степпинга. Код выхода 0 — успех.

## Ручной тест 4.1 — сцена мира и камера

Запуск (окно, не headless):

```sh
cd godot && godot
```

Чек-лист (глазами, окно **1920×1080** — окно по умолчанию зафиксировано в project.godot; для замера FPS запуск F5 из редактора с открытой панелью «Отладка → Мониторы»):
1. Видна стартовая площадка (тёмно-зелёный квадрат ~18×18 юнитов) с тёплым еле заметным гридом (клетка = 1 юнит ядра) и янтарный корпус ровера где-то на паде (стартовый зум ~16.7 px/юнит — пад ~300 px).
2. СКМ-drag (или зажатый **пробел** + ЛКМ-drag) панорамирует камеру; курсор «тащит» мир.
3. Колесо мыши зумит к точке под курсором; зум ограничен (далеко — весь грид, близко — отдельные клетки).
4. Свет тёплый (не серый/синий), тени от ровера мягкие.
5. FPS ≥ 60 (монитор производительности: отладка → Monitors, или `--verbose`).

Камера — Camera2D: ядро плоскостное (Vec2), сцена работает в юнитах ядра, визуальный масштаб задаёт стартовый зум 16.67 px/юнит (пад ≈300 px).

## Ручной тест 4.2 — ровер-модель и плавное движение

Запуск (окно): `cd godot && godot`, затем в симуляции дай команду роверу (пока через debug-канал; в 5.4 появится кнопка Run). Быстрый вариант без UI — временно добавить в `scripts/main.gd`:

```gdscript
func _ready() -> void:
	print("Neogen shell ready")
	await get_tree().create_timer(0.5).timeout
	var sim := get_node("Sim")
	sim.debug_move_rover(1, 6.0, 6.0)
```

Чек-лист (глазами):
1. Ровер читается как машина: янтарный направленный корпус (нос = маркер направления), а не квадрат.
2. При движении корпус доворачивается по курсу (плавно, без щелчков) и слегка вытягивается вперёд/сжимается поперёк; на парковке форма возвращается к исходной (сквош уходит).
3. За ровером тянется затухающий след (янтарная линия, хвост бледнеет), пропадающий по мере стояния на месте.
4. Движение плавное, без дёрганья на стыках тиков (chase-интерполяция 3.3 + сглаживание поворота).
5. FPS ≥ 60 (монитор производительности).

## Ручной тест 4.3 — HUD

Запуск (окно): `cd godot && godot` (можно с временным сниппетом движения из «Ручного теста 4.2»).

Чек-лист (глазами):
1. В левом верхнем углу полупрозрачная панель «NEOGEN» с тремя строками: tick / seed / scripts.
2. Seed показывает 42 (или выставленное в инспекторе SimNode до запуска).
3. Tick растёт по ходу симуляции (шаг 30/с при работающих тиках).
4. Без скриптов — «scripts: none»; после attach скрипта — «#1: running» (или finished); при ошибке скрипта — «#1: error (…hud boom…)» с текстом причины.
5. Панель не мешает камере (drag/зум поверх неё работают), FPS ≥ 60.

## 6.5 Фасад — ручные проверки (спринт 6.5.1–6.5.7)

Один запуск: `cd godot && godot` (окно 1920×1080; FPS — Monitors, цель ≥ 60 на машине разработки; сцена: CPUParticles×36 + PointLight2D + DirectionalLight с тенями + ~9k статичных прямоугольников земли — на RTX 4070 с запасом).

### Целостность картины (6.5.7)

1. Сцена читается как **единый мир**, не набор эффектов: небо-градиент неразрывно с землёй, виньетка мягко замыкает кадр, свет один и тёплый.
2. При любом зуме (колесо, 20..50 px/юнит) экран остаётся **внутри нарисованной земли** — «остров в небе» не виден.
3. Палитра согласованная: янтарь (ровер, маяк, энергия) / тёплая зелень (мох, экология) / стекло (купол, кабина, кристаллы) — без спорящих пятен.
4. HUD/консоль/редактор читаются поверх картины без борьбы.
5. FPS ≥ 60 при живых частицах и свете.

### Небо и земля (6.5.1 + 6.5.3)

1. Фон — тёплый градиент (янтарный горизонт → бирюзовый зенит), не серый клир.
2. Земля вокруг пада — мозаика (мох светлый/тёмный, земля, редкие камни), крупными пятнами гуще/реже.
3. Спирали травы группами, скалы с гранью света, кристаллы со свечением — минимум один в стартовом кадре.
4. Пад читается как площадка; patrol-маршрут 0..8 чист от пропсов.
5. Грид-линии не спорят с землёй.

### Поселение (6.5.4)

1. Кластер из купола (свечется изнутри) + 2–3 наклонных панелей + мачты с пульсирующим маяком, в стороне от пада.
2. Тени структур согласованы со светом; контактные тени заземляют.
3. Ничего не перекрывает ровер/HUD/маршрут.

### Ровер (6.5.1 + 6.5.5)

1. Двухслойный: янтарный корпус, стеклянная кабина с бликом, антенна с огоньком; колёса крутятся от скорости, на стоянке стоят.
2. Парение: корпус мягко «дышит»; сквош при разгоне сохранён.
3. След: тёплое светящееся облачко, плавно тает; вокруг ровера тёплый ореол света.

### Атмосфера (6.5.2)

1. По углам — мягкое затемнение (виньетка), центр чистый.
2. Редкие тёплые пылинки дрейфуют вверх по ветру, следуют за камерой.
3. Свет мягкий тёплый, без жёлтой грязи и серости.

### Пульс Ноосферы (6.5.6 — прототип)

Дисклеймер: значения — Godot-прототип до фазы 7; настоящие индексы переедут в ядро (7.3), шкалы станут их зеркалом.

1. На HUD две шкалы: энергия (янтарь) и экология (зелёная) с числами.
2. Движение — энергия убывает; стоянка — восстанавливается; экология реагирует плавно; значения в 0..100.

## Ручной тест 6.1 — новый игрок за 2 минуты

Запуск: `cd godot && godot` (окно 1920×1080, F5 из редактора для fps).

1. **0:00** — при старте видна подсказка «NEOGEN — с чего начать». Читаешь, жмёшь «Понятно, поехали» (или Esc).
2. **0:20** — F12 → в списке выбираешь `scripts/patrol.lua` (демо-скрипт патруля, откомментирован по-русски — почитай, это описание всего API).
3. **0:40** — Run. Ровер едет по квадрату, консоль (`) показывает «патруль: вершина (…)».
4. **1:10** — правишь `SIDE = 8` на `SIDE = 3`, сохраняешь — маршрут сжимается сам (hot-reload).
5. **2:00** — Stop останавливает. Дальше: пиши свои скрипты, `scan_result()` и `act` — в описании API в автодополнении редактора.

## Редактор скриптов (фаза 5)

Панель редактора в правой части экрана, **переключение — F12**. Список `.lua`-файлов из папки `scripts/` в корне репо, кнопки New / Save / Refresh / **Run** / **Stop** + чекбокс **auto-restart**. Запись — **полная перезапись файла** (MVP, без диффов).

**Run/Stop/hot-reload (5.4):** Run исполняет текущий файл на первом (единственном) ровере; повторный Run — stop+detach старого + свежий attach. Stop паркует скрипт **и** чистит очередь команд ровера (команды принадлежат роверу — иначе Finished-скрипт продолжал бы ехать). Hot-reload: опрос файла раз в секунду; изменение привязанного файла → перезапуск (если auto-restart включён). Полный цикл: написал → Run → видишь → отредактировал → перезапустился. Путь к папке — dev-сборка через `ProjectSettings.globalize_path("res://")/../scripts`: в экспортированной игре `res://` только для чтения — переключение на `user://`-воркспейс отложено до фазы экспорта (см. доку `script_files.gd`).

**Известный баг (Godot 4.7.2 + gdext 0.5.5):** headless editor-импорт с класс-регистрирующим расширением сегфолтится на выходе процесса — ПОСЛЕ записи `.godot/extension_list.cfg`. Сам краш безвреден; чистый прогон `godot --headless --quit` загружает extension без ошибок (CI проверяет именно это). Пересмотреть при обновлении Godot/gdext.
